## :dart: O guia para alavancar a sua carreira

> Composer é o gerenciador de dependências oficial do PHP: se o seu projeto roda Laravel, Symfony, WordPress moderno ou qualquer pacote do [Packagist](https://packagist.org/), ele passa pelo Composer. Saber usá-lo de verdade — não só `composer install` — significa entender `composer.json`, versionamento semântico, autoloading PSR-4, scripts de ciclo de vida, repositórios privados e como publicar seus próprios pacotes. Este guia reúne documentação oficial, cursos, livros, ferramentas do ecossistema PHP (análise de dependências, segurança, deploy) e um capítulo dedicado a usar IA na prática com Composer — tudo verificado e organizado para quem já tem PHP instalado e quer dominar o gerenciador de pacotes por trás de praticamente todo projeto PHP do mercado.

## 🚀 Por onde começar

1. Instale o Composer seguindo o [guia oficial de download](https://getcomposer.org/download/) (funciona em Windows, Linux e macOS).
2. Leia a [introdução oficial](https://getcomposer.org/doc/00-intro.md) para entender o que o Composer resolve e por que ele existe.
3. Siga o [uso básico](https://getcomposer.org/doc/01-basic-usage.md): `composer require`, `composer install` e o que muda entre `composer.json` e `composer.lock`.
4. Entenda o [versionamento semântico](https://getcomposer.org/doc/articles/versions.md) usado pelo Composer para resolver `^` e `~` nas versões.
5. Explore o [Packagist](https://packagist.org/) — repositório oficial de pacotes PHP — para ver o que já existe antes de reescrever algo do zero.
6. Aprenda a estruturar o [autoload PSR-4](https://www.php-fig.org/psr/psr-4/) do seu próprio código dentro do `composer.json`.
7. Quando o projeto crescer, veja como criar e [publicar seu próprio pacote](https://getcomposer.org/doc/02-libraries.md) no Packagist.

## 🤖 IA na prática

Usar IA com Composer funciona melhor quando ela vira uma segunda opinião sobre dependências e configuração — e não uma fonte de verdade sobre o que instalar.

**Para aprender**
- Cole o conteúdo do seu `composer.json` e peça para a IA explicar cada dependência: para que serve, se está desatualizada e se existe alternativa mais leve.
- Peça para explicar, linha a linha, a saída de um `composer audit` real do seu projeto: qual vulnerabilidade é séria, qual pode esperar e por quê.
- Peça exemplos comentados de scripts do Composer (`pre-install-cmd`, `post-update-cmd`) para entender quando cada hook roda no ciclo de vida.
- Peça para comparar um range de versão (`^2.1`, `~2.1`, `2.1.*`) com exemplos de quais versões cada um aceitaria instalar.

**Para trabalhar**
- Use [GitHub Copilot](https://github.com/features/copilot), [Cursor](https://cursor.com/) ou [Claude Code](https://code.claude.com/docs/en/overview) para gerar a configuração inicial de um `composer.json` para publicação, escrever scripts de build/deploy e revisar o changelog antes de dar tag em uma nova versão.
- Peça para a IA resumir os alertas do [GitHub Advisory Database](https://github.com/advisories?query=ecosystem%3Acomposer) de um repositório e priorizar quais atualizações de dependência aplicar primeiro.
- Antes de aceitar uma sugestão de código que adiciona uma dependência nova via Composer, peça para a IA justificar a escolha frente a alternativas já instaladas no projeto — evita inflar o `vendor/` sem necessidade.
- Vale acompanhar como a própria comunidade PHP está usando IA para segurança da cadeia de suprimentos: a [PHP Foundation contratou um "Ecosystem AI Security Engineer"](https://stitcher.io/blog/php-ecosystem-security-team) em 2026 para ajudar a encontrar e corrigir vulnerabilidades em pacotes do ecossistema.

**Limites e boas práticas**
- IA pode **inventar nomes de pacotes** que não existem no Packagist (alucinação clássica em geração de código). Sempre confira o nome exato em [packagist.org](https://packagist.org/) antes de instalar — um nome parecido com o certo é um vetor real de ataque (typosquatting).
- Não peça para a IA "resolver" um `composer audit` automaticamente sem revisar: subir uma dependência para a versão mais recente sugerida pode quebrar compatibilidade com o PHP ou com outras bibliotecas do projeto.
- Nunca cole tokens de repositórios privados, credenciais do `auth.json` ou segredos de CI em ferramentas de IA sem a política da sua empresa.
- A decisão final sobre qual dependência entra no projeto é sua: manutenção ativa, licença e compatibilidade de versão do PHP importam mais do que a sugestão mais rápida.

## 🎓 Certificações

Não existe certificação oficial do Composer — a ferramenta em si não tem programa de certificação próprio. A certificação mais próxima do tema, focada na linguagem que o Composer serve, é a **Zend Certified PHP Engineer**, hoje mantida pela Perforce/Zend, que cobra conhecimento prático do ecossistema PHP (incluindo gerenciamento de dependências).
- [Zend Certified PHP Engineer](https://www.zend.com/certification) — Certificação paga que avalia conhecimento prático de PHP, incluindo boas práticas de projeto e dependências.
